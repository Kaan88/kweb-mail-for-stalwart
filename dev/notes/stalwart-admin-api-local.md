## 0. Headlines for the design
1. **The management API is JMAP.** POST /jmap (or /jmap/) with methods named `x:<Object>/get|query|set|changes` (for example `x:Domain/query`). The session's `urn:stalwart:jmap` capability is advertised, but a call works without it in `using` (only core was passed and it worked). An unknown capability URI in `using` gives HTTP 400 `{"type":"urn:ietf:params:jmap:error:notRequest",...}`. The legacy REST /api/queue, /api/logs, /api/reports, /api/settings, /api/license, /metrics, /api/telemetry/* all return 404 (verified, also as admin). Only the few /api/* paths in section 7 exist.
2. **The Enterprise error is a normal JMAP method error, HTTP 200.** Exact answer: `["error",{"type":"forbidden","description":"This feature is only available in the Enterprise edition. Obtain your trial license at https://license.stalw.art/trial."},"<callId>"]`. The same `forbidden` type is used for "not authorized", so the app must match on the description text (substring "only available in the Enterprise edition"), not on the type.
3. **The licence check comes before the permission check.** A normal user calling `x:MaskedEmail/get` gets the Enterprise error, not "not authorized". Calling a non-Enterprise admin object as a normal user gives `{"type":"forbidden","description":"You are not authorized to perform this action"}`.
4. **MaskedEmail is Enterprise in this 1.1.0 build.** It is gated for admin and normal user alike (details in section 4). The owner's remark that masked email moves to the GPL edition next release fits this: the gate is an `enterprise:true` flag in the schema (section 3). So the app needs a feature probe, not an edition check.
5. **Edition detection: GET /api/account** (Bearer or Basic) returns `{"permissions":[...],"edition":"community","locale":"en-US"}` for every login (recovery admin, admin@kweb.test, tester). With a licence it presumably says something else (value unverified, my server has none). Permissions are camelCase names such as `sysMaskedEmailQuery`, `liveMetrics`, `sysQueuedMessageQuery`. Counts: tester 253, admin@kweb.test 664, recovery admin 646.
6. **Admin account types.** admin@kweb.test (account id "b", role Admin) is a real account, so a signed-in admin app user is this one. The recovery admin `admin` is not an account: its JMAP session shows accountId "d333333" (not a real id), and for account-bound objects (ApiKey, AppPassword, Passkey) it answers `forbidden "Account not found."`.

## 2. Management objects and how they are read
`stalwart-cli` v1.0.14 is a native binary (no JS source to read). Commands: get, query, create, update, delete, describe, apply, snapshot. Global flags: --url, --user, --password, --api-key (Bearer), --no-color, --debug (prints only method and URL: `GET /api/schema`, `GET /jmap/session`, `POST /jmap`; no bodies). It reads /api/schema (needs auth, about 1.1 MB, gzip) and talks JMAP to POST /jmap with `x:` methods.

`stalwart-cli describe` lists 162 object types; the full list is in scratchpad/ent/describe.txt. Examples: Account (variants User/Group), Domain, Role, Tenant, Sharing [singleton], QueuedMessage, Tracer, Trace, Log, Metric, Metrics [singleton], DmarcExternalReport, DmarcInternalReport, TlsExternalReport, TlsInternalReport, ArfExternalReport, Task, ClusterNode, Enterprise [singleton], MaskedEmail, ArchivedItem, AiModel, Alert, Action, MailingList, Application, ApiKey, AppPassword, Passkey, OAuthGrant, OAuthClient, PublicKey, SpamTrainingSample, Certificate, DkimSignature, SieveSystemScript, WebHook, BlockedIp, AllowedIp, Directory, NetworkListener, and so on.

Request shapes (all verified, HTTP 200):

## 3. What the open edition refuses, and how
The schema marks it. In /api/schema, `objects[<name>].enterprise: true` and `fields[<schema>].properties[<field>].enterprise: true`. The app can read this once per server and hide those features before calling. The five-minute rule: the flag in the schema decides, and the runtime error is the safety net.

**Enterprise objects (10), all answer the Enterprise error on get, query and set for every user:**
x:AiModel, x:Alert, x:ArchivedItem, x:MaskedEmail, x:Metric, x:MetricsStore, x:SpamAi, x:Tenant, x:Trace, x:TracingStore.
Verified by actual call: ArchivedItem, MaskedEmail, Metric, Trace gave the Enterprise error on `query` as admin@kweb.test, as recovery admin, and (ArchivedItem, MaskedEmail) as tester. Metric and Trace gave the plain "not authorized" for tester. Note: in my sweep AiModel, Alert, SpamAi, MetricsStore, TracingStore and Tenant `query/get` returned OK as admin (empty or singleton), so for these the licence gate seems to apply on write/use only, not on read. That was not tested with writes.

**Enterprise fields (read is fine, writes presumably refused; not tested):** every `memberTenantId` (Account, Role, Domain, DnsServer*, DkimSignature, MailingList, OAuthClient, directories, reports, AcmeProvider), Authentication.defaultTenantRoleIds, Cache.tenants, CalendarAlarm.template, CalendarScheduling.emailTemplate and httpRsvpTemplate, DataRetention.archiveDeletedAccountsFor, archiveDeletedItemsFor, holdMetricsFor, holdTracesFor, metricsCollectionInterval, Domain.logo, directoryId and allowScimProvisioning, Email.maxMaskedAddresses (value 5 on this server), Enterprise.logo, UserAccount/GroupAccount.externalId, LdapDirectory.urlFailover, MySqlStore/PostgreSqlStore.readReplicas, OidcDirectory.trustedProvider, Search.indexTelemetry, SpamClassify.aiFacts, aiGate and aiVerdict. The full list is in the section's source: scratchpad/ent/schema.json.

**Live streams are absent, not forbidden:** GET /api/token/metrics and /api/token/tracing answer 404 `{"type":"about:blank","status":404,"title":"Not Found","detail":"The requested resource does not exist on this server."}` for every user. So live metrics and live tracing do not exist on this server (they are the Enterprise dashboard and live tracing). `/api/token/delivery` exists (200 for both admins, 403 `"You do not have enough permissions to access this resource."` for tester).

**Open edition keeps working:** Account, Domain, Role, Log, QueuedMessage, Tracer, ClusterNode, all report objects, Task, all settings singletons (except MetricsStore, TracingStore, SpamAi), Action, ApiKey, AppPassword, Passkey, OAuthGrant, PublicKey, SpamTrainingSample.

## 10. Summary list: what an open-edition server refuses and how
1. Enterprise objects (MaskedEmail, ArchivedItem, Metric, Trace and the write side of AiModel, Alert, SpamAi, Tenant, MetricsStore, TracingStore): HTTP 200 with a JMAP method error `forbidden`, description starting "This feature is only available in the Enterprise edition." No new error type.
2. Live metrics/tracing stream tokens: HTTP 404 on /api/token/metrics and /api/token/tracing.
3. Enterprise-only fields: listed in section 3; reads work, writes unverified.
4. Normal users on admin objects: `forbidden` "You are not authorized to perform this action".
5. Recovery admin on per-account objects: `forbidden` "Account not found."
6. Unknown method: `unknownMethod` with the method name as description. Unknown capability in `using`: HTTP 400 `urn:ietf:params:jmap:error:notRequest`.
7. Sorting Log by anything other than id: `unsupportedSort`.
Detection recipe for the app: (a) GET /api/account, `edition` and `permissions`; (b) GET /api/schema, `objects[...].enterprise`; (c) treat any `forbidden` whose description contains "Enterprise edition" as "feature unavailable" and hide the entry; (d) treat any other `forbidden` as "no permission".

Not verified: any /set call (create, update, destroy), the `edition` value and the `Enterprise` singleton under a real licence, `x:Metric` and `x:Trace` result shapes (refused here; Metric shapes are in describe: Counter/Gauge/Histogram variants with metric, nodeId, timestamp, count, sum), `calculateTotal` and filter syntax beyond `limit`, the SSE streams, and which OAuth scope the admin permissions need.
