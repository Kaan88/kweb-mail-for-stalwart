# Bulwark filters: what the app must match (researched 2026-11-16 from bulwarkmail/webmail)

Sources: lib/sieve/generator.ts, lib/sieve/parser.ts, stores/filter-store.ts, components/filters/filter-rule-modal.tsx, components/settings/filter-settings.tsx. Fetch them raw from https://raw.githubusercontent.com/bulwarkmail/webmail/main/<path> when you need the exact code (the generator's exact Sieve per construct must be copied byte for byte; copy its test fixtures from components/filters/__tests__ and lib/sieve/__tests__ if present).

## Script
- Order: metadata comment, `require [...]` (sorted, deduplicated, includes external requires), optional vacation include (`# Vacation auto-reply` then `include :personal :optional "vacation";`, wrapped in an envelope test when an audience is set), optional vacation reply, optional vacation forward block (marker constant), one block per enabled Bulwark rule, then external blocks verbatim under `# --- External rules (managed outside Bulwark) ---`. Blank lines between sections, trailing newline.
- Metadata: `/* @metadata:begin` newline, one-line JSON, newline `@metadata:end */`. Any `*/` in the JSON is written `*\/`. `version` 1, or 2 when any rule has a period or a regex condition, forwarding is on, or a vacation audience is set. Keys: `rules` (Bulwark-origin rules only, each stripped to id, name, enabled, matchType, conditions, actions, stopProcessing, and when set includeSpam, activeFrom, activeUntil), optional `vacation`, `includeVacation`, `vacationForward`, `vacationAudience`.
- Rule block: `# Rule: <name, whitespace collapsed>` then `if <test> {` then actions indented 4 spaces then `}`. A rule with no conditions or no actions, an invalid header name or an unusable period is skipped. One condition as is; several in `allof(...)` for matchType all, `anyof(...)` otherwise; a period test comes first inside an `allof`. Move/copy rules add `not spamtest :percent :value "ge" :comparator "i;ascii-numeric" "50"` unless includeSpam, only when the server has spamtestplus and relational.
- Script choice: skip the reserved `vacation` script; load the active script, else the first; a new one is named `filters`. Saving activates the filters script. When the auto-reply is on, the filters script includes the vacation script so both run.
- Foreign content: a script with metadata that fails to parse is opaque (raw editor only, written back unchanged). Without metadata, `if` blocks the parser understands become external rules (read-only, origin label from comments: Roundcube `# rule:[Name]`, Nextcloud region markers, Horde, Kolab, Dovecot, Thunderbird, else External); unknown top-level statements become opaque rules kept verbatim. The app does not parse Sieve: it keeps everything after the last Bulwark rule block verbatim as the external section, and a script without metadata is shown as foreign with its text, exactly as today, but never overwritten.

## Rule model (JSON)
- `{id, name, enabled, matchType: "all"|"any", conditions: [...], actions: [...], stopProcessing, includeSpam?, activeFrom?, activeUntil?}`; ids are strings; `origin` absent or "bulwark".
- Condition `{field, comparator, value, headerName?}`: fields `from, to, cc, subject, header, size, body, attachment, all`; `value` a string or an array of strings (comma-separated input becomes an array; one entry stays a string).
- Comparators per field: subject/body/header: contains, not_contains, is, not_is, starts_with, ends_with, matches (+ regex when the server supports it); from/to/cc: the same plus address_is, domain_is; size: greater_than, less_than (generator emits `size :over N` for greater_than, else `:under N`; N digits with optional K/M/G); attachment: has_any, has_type; all: none.
- Action `{type, value?, mailboxId?, keepCopy?}`: move, copy, forward, mark_read, star, add_label, discard, reject, keep, stop. Forward hidden when the server's redirect limit is 0; disabled when the limit is reached.

## Sieve per construct (from the generator)
- all: `true`; size: `size :over N` / `size :under N`; body: `body :is|:contains|:regex <values>`; attachment has_any: `header :mime :anychild :contains "Content-Disposition" "attachment"`; attachment has_type: `header :mime :anychild :matches ["Content-Disposition", "Content-Type"] "*.<ext>*"`; address_is / domain_is: `address [:domain ]:is "<Header>" <values>`; contains `header :contains`, not_contains `not header :contains`, is `header :is`, not_is `not header :is`, starts_with `header :matches` with `v*`, ends_with with `*v`, matches `header :matches`, regex `header :regex`. Values: one as a plain string, several as `["a", "b"]`. Header names: From, To, Cc, Subject; custom trimmed, must match `^[A-Za-z0-9_-]+$`, blank becomes X-Unknown.
- Actions: flag actions first (mark_read `addflag "\\Seen";`, star `addflag "\\Flagged";`, add_label `addflag "$label:<value>";`), then move `fileinto "<path>";` or `fileinto :mailboxid "<id>" "<path>";` when the server has mailboxid and the rule has one; copy the same with `:copy`; forward `redirect "<addr>";` with `:copy` when keepCopy; discard `discard;`; reject `reject "<text>";`; keep `fileinto "INBOX";`; stop `stop;` (appended once when stopProcessing).
- require: spam guard spamtestplus, relational, comparator-i;ascii-numeric; period PERIOD_REQUIRES (see period.ts); body; mime; regex; fileinto (+copy, mailbox, mailboxid); imap4flags; reject; vacation; include (+envelope).

## Editor (filter-rule-modal.tsx)
Title New rule / Edit rule. Rule name (required, 200 chars). Match type All / Any toggle. Optional suggestion chips (quick rules from a message: sender, domain, list). Condition rows: field select in the order From, To, Cc, Subject, Header, Size, Body, Attachment, All messages; header name input for Header (validated); comparator select per field as above; value input (hidden for All and has_any; numeric for size; text otherwise; comma-separated gives several values; regex not split); Add condition; remove disabled on the last row. Action rows: type select Move, Copy, Forward, Mark as read, Star, Add label, Discard, Reject, Keep; folder picker for move/copy (tree order, own folders only; stores id and path); forward address plus "keep a copy"; reject text; label from the user's keywords; Add action; remove disabled on the last row. Stop processing checkbox (old `stop` actions convert to it). Include spam checkbox only with a move/copy action. Active period: "limit to period" with start and end date-time, entered in local time, stored as UTC; only when the server supports it or the rule has one. Validation after Save: empty name, no condition with a value, invalid header, regex that does not compile, incomplete action (folder, label, address, reject text), no actions, period half-filled or reversed. Cancel asks to discard when changed.

## Settings page (filter-settings.tsx)
Rule rows: drag handle (or up/down), enable switch per rule, name, one-line summary (up to two conditions joined by AND/OR, +N, up to two actions), period badge, delete. External or opaque rules: lock icon, origin label, read-only, raw block in monospace. Every toggle, reorder, delete and edit saves at once; a failed save reverts and shows an error; delete has Undo instead of a confirmation. Add rule hidden for an opaque script. Raw editor for advanced use and always for an opaque script; "Reset to visual builder" asks first. Warnings: opaque script, vacation active (informational), forwarding unavailable (limit 0), forward limit exceeded. States: not supported, loading, error, no rules. No global on/off in Bulwark; the app keeps its own "Use these filters" switch (activate or deactivate the script) because the owner asked for it.
