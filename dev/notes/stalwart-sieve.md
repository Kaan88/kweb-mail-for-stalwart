9. WHAT THE APP SHOULD NEVER GENERATE (refused, ignored or silently wrong)
- A script that uses an extension without the matching require (fileinto, mailbox for :create, copy for :copy, mailboxid, special-use, imap4flags, body, date, relational, variables, reject, vacation...): refused, error {"type":"invalidScript","description":"Undeclared capability 'x' at line N, column M."}. The require list must be complete and must repeat sub-extensions ("mailbox" for :create, "copy" for :copy).
- require of an extension that is not in sieveExtensions: accepted by validate and set but the script then fails silently at delivery (mail goes to Inbox, nothing applied). Check the capability list before emitting.
- fileinto of a folder that does not exist without :create: accepted, but the mail goes to Inbox (the rule does nothing). Use :create (+require "mailbox") or fileinto :mailboxid "<JMAP id>" "<name>" (+ require "mailboxid"; the second string is mandatory). Role names like "Trash" or "Junk" are not folder names here; the folder is "Deleted Items"/"Junk Mail" in this setup. Only the display name, or the path "Parent/Child", or :mailboxid/:specialuse work. The "Parent.Child" dot is not a separator.
- :mailboxid/:specialuse without the string argument that follows (a single string with only the tag) is a syntax error.
- More than maxNumberRedirects (1) redirects per message: accepted by validate, enforced at delivery (the extra ones do not go out).
- A script over maxSizeScript (102,400 bytes): tooLarge on set, invalidScript on validate. More than 100 scripts: overQuota.
- A script named "vacation" (reserved), or any update/rename/activate/destroy on the vacation script through SieveScript/set: forbidden. Use VacationResponse/set.
- Name collisions (case-insensitive) -> alreadyExists with existingId. Destroying an active script: scriptIsActive; destroying with the deactivation in the same SieveScript/set call also fails (use a second call).
- Do not assume SieveScript/changes exists (unknownMethod), nor an inline "content" property in SieveScript/set (invalidProperties). Always go through upload or Blob/upload.
- Do not send mail with Cc/To outside @kweb.test when testing (JMAP submission queues it for real MX delivery).
- Setting VacationResponse isEnabled:true (or activating any other script) displaces whatever script is active; the app must warn and re-get state after every activate/deactivate (the set answer does not list what was deactivated).
- reject/ereject bounce to the sender (DSN); they should be an advanced option at most.
